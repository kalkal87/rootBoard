# Lean Wastes

## Core idea

Lean waste analysis assumes most processes contain steps that consume time
or resources without adding value for the end recipient. Classic categories
include waiting, rework/defects, overproduction, extra processing,
motion/handoffs, transport, inventory/queueing, and unused skills. Naming
which category a wasteful step falls into makes the fix more concrete than
just calling the process "slow."

## Reasoning steps

1. Reconstruct the process or sequence of steps described in the input as a
   rough ordered flow, using only what is stated or clearly implied.
2. For each step, ask whether it adds value the end recipient would care
   about, or whether it exists for another reason (waiting on approval, a
   handoff, correcting a prior mistake, doing more than needed).
3. Where a step looks like waste, classify it under the most fitting
   category (waiting, rework, overproduction, extra processing,
   motion/handoffs, transport, inventory/queueing, unused skills) rather
   than leaving it as a generic complaint.
4. Note where the input doesn't give enough detail to tell whether a step is
   value-adding or waste — put that in open questions rather than guessing
   at the process's internals.
5. Prioritize the waste categories that recur most often, or that the
   input's own language treats as most costly (time, money, frustration),
   over listing every minor inefficiency with equal weight.

## What it tends to surface

Recurring inefficiencies baked into how work actually flows — handoffs,
rework loops, and idle time that a single-symptom framework would treat as
one problem rather than a pattern.

## Known blind spot

Lean wastes analysis is built for repeatable operational processes; it
strains to say anything useful about one-off incidents, judgment calls, or
problems that are really about relationships and incentives rather than
workflow steps.
